# CRVU на GitHub Pages

GitHub Pages отдаёт только готовые файлы и не запускает Flask. Поэтому на Pages публикуется
**статическая сборка** публичного сайта, а Flask-сайт с админкой остаётся как есть — для
локальной работы и для будущего сервера с Python.

Сборку делает `scripts/export_static.py`. Страницы рендерит само приложение (как анонимный
посетитель), файлы скачиваются через его публичные маршруты. Поэтому в сборку попадает только
опубликованное и только то, на что ссылаются страницы. Результат — `build/pages/`.

## Сборка и просмотр на своём компьютере

```bash
source .venv/bin/activate
python scripts/export_static.py --base-path /имя-репозитория           # → build/pages/
python scripts/export_static.py --base-path /имя-репозитория --serve   # и просмотр
# открыть http://127.0.0.1:8000/имя-репозитория/
```

- `--base-path` (или переменная `CRVU_BASE_PATH`) — адрес сайта от корня домена. Для
  `https://<user>.github.io/<repo>/` это `/<repo>`; для `<user>.github.io` и своего домена — пусто.
  Сборка с одним базовым путём на другом адресе работать не будет — пересоберите.
- `--form-endpoint` (или `CRVU_FORM_ENDPOINT`) — адрес приёма заявок конфигуратора, см. ниже.
- `--out` — другая папка вывода. Сборка перезаписывает папку, только если в ней лежит её
  прежний результат (файл `.crvu-static-export`); чужие папки и папки проекта не трогает.
- Сборка останавливается с ошибкой, если страница ссылается на файл, которого нет или который
  не опубликован, и если проверка нашла в результате закрытые данные (см. «Что не публикуется»).
- Просмотр (`--serve`) ведёт себя как Pages: базовый путь, `/portfolio` → `portfolio.html`,
  `404.html`. Перемотку видео по Range он не поддерживает — на Pages она есть.

## Что работает на Pages

- Главная и разделы-шторки по своим адресам (`/<repo>/portfolio`, `/<repo>/contacts` и др.);
  `/about` — страница-переход к блоку «О нас» на главной; якоря внутри страницы.
- Фон: петля `pre-video.mp4` вверху и внизу, сборка стенда по прокрутке, уменьшение движения.
- Портфолио: фильтры (с адресом в строке браузера), галерея фото, видео проектов.
- Видеоотзывы: RuTube и свои видеофайлы опубликованной библиотеки.
- Конфигуратор: размеры, план, ориентир бюджета.
- Кнопка «Связаться» и её меню, контакты, соцсети, копирование email.
- Форма «Заявка» в шапке и подвале — как и на сервере: если в `site.json → request.email` указан
  адрес, открывает почтовую программу посетителя; сейчас адреса нет, и форма честно пишет, что
  заявка не отправлена, и отсылает к контактам.

## Что требует Flask или внешнего адреса

| Возможность | На Pages |
|---|---|
| Админка `/admin`, вход, «Редактор», черновики, предпросмотр, «Опубликовать», история версий | нет — только на Flask-сервере. Контент правится локально, затем сайт пересобирается |
| Загрузка фото, видео, обложек, импорт папок и ZIP | нет — только в админке на Flask |
| Заявка «Обсудить проект» из конфигуратора (`POST /request/design`, сохранение в `requests/`, раздел «Заявки») | только с внешним адресом приёма (ниже); без него форма не отправляется |
| Ограничение частоты заявок, проверка заявки на сервере | на стороне внешнего сервиса |
| Заголовки безопасности (CSP и др.) | CSP — в `<meta>` каждой страницы; `frame-ancestors` и другие заголовки Pages не задать |

**Заявка конфигуратора.** Без адреса приёма в окне заявки сразу написано, что онлайн-отправка
не работает. Кнопка не отправляет данные и не показывает «Спасибо»: она отсылает к телефону,
почте и кнопке «Связаться». Чтобы принимать заявки, задайте https-адрес своего обработчика
в `CRVU_FORM_ENDPOINT` или в переменной репозитория. Обработчик:

- принимает `POST` с `FormData`: `contact`, `website` (ловушка для ботов — заявку с непустым полем
  отбросить) и параметры стенда;
- разрешает CORS для адреса сайта, включая заголовки `X-Requested-With` и `Accept`;
- отвечает JSON: `{"ok": true}` или `{"ok": false, "message": "…"}`; любой другой ответ форма
  считает неудачей и сообщает об этом посетителю.

Сервис для этого не выбран: выбор и настройка — отдельное решение.

## Публикация через GitHub Actions

Workflow уже лежит в `.github/workflows/pages.yml`. Он собирает сайт и публикует только `build/pages`.

1. Создайте репозиторий и отправьте в него проект (`.gitignore` уже исключает закрытое — см. ниже).
2. Фото и видео для сборки уже лежат в `pages-media/` (см. ниже) — отдельно ничего делать не нужно.
3. Settings → Pages → Build and deployment → Source: **GitHub Actions**.
4. Необязательно: Settings → Secrets and variables → Actions → Variables → `CRVU_FORM_ENDPOINT`.
5. Actions → «GitHub Pages» → Run workflow. Базовый путь workflow берёт сам
   (`actions/configure-pages`): `/<repo>` для сайта проекта, пусто для своего домена.
6. Публикацию при каждом push в `main` включите, раскомментировав `push:` в workflow.

Перед первой публикацией соберите сайт локально и посмотрите итоговую сводку и `build/pages/`.

## Фото и видео для Pages: `pages-media/`

`content/media/` в Git не хранится: там лежат и фото черновиков. Сборке в Actions нужны только
публичные файлы, поэтому они лежат отдельно, в `pages-media/` (хранится в Git), а список —
в `pages-media/MANIFEST.tsv`: SHA-256, размер и путь каждого файла. Это ровно файлы, на которые
ссылается опубликованный сайт: фото и их версии у опубликованных проектов, обложки включённых
видеоотзывов. Ни фото черновиков, ни неиспользуемых файлов, ни оригиналов там нет.

```bash
python scripts/export_static.py --sync-media            # сборка по content/ → обновить pages-media/ и список
python scripts/export_static.py --sync-media --prune    # то же, если что-то сняли с публикации
python scripts/export_static.py --media-dir pages-media # сборка только из pages-media/ — как в Actions
```

- После публикации, снятия с публикации или замены фото в админке выполните `--sync-media` и
  просмотрите изменения в `MANIFEST.tsv` перед коммитом. Обычная сборка по `content/`
  предупреждает, если `pages-media/` отстала.
- `--sync-media` не удаляет файлы, которые сайт больше не использует, а останавливается со списком.
  Убрать их можно только с `--prune` (это копии — исходники остаются в `content/media/`).
- Сборка из `pages-media/` останавливается с понятным сообщением, если:
  - файлы папки не совпадают со списком (лишний, недостающий или изменённый файл);
  - опубликованный проект или видеоотзыв ссылается на файл не из списка;
  - страница ссылается на файл, которого нет;
  - в списке есть файлы, которые сайт больше не использует.
  Битых картинок на опубликованном сайте не будет: сборка просто не пройдёт.

## Что никогда не публикуется и не коммитится

- `.env` и любые `.env.*` — ключ сессий, логин и хеш пароля админки.
- `requests/` — заявки посетителей (персональные данные).
- `content/originals/` — исходные фото с EXIF и GPS; `project_photos/` — подготовленные к импорту фото.
- `content/.drafts/`, `content/.history/`, `content/.cache/`, `content/.lock` — черновики, история
  версий, служебные файлы админки.
- `backup/` — резервные копии; `build/`, `dist/`, `CRVU.html`, `ЦРВУ 2.0.html` — сборки и старые
  снимки сайта (десятки МБ, контент может быть устаревшим).
- Фото и видео неопубликованных проектов и выключенных роликов; весь `content/media/` целиком —
  в Git попадает только `pages-media/`.

Проверка сборки (`audit` в `scripts/export_static.py`) не пропускает в `build/pages` файлы вне
`static/` и `media/`, JSON, исходники, пути с `.env`, `originals`, `.history`, `.drafts`,
`.cache`, `requests`, `admin`, `backup`, фото неопубликованных проектов, видео вне опубликованной
библиотеки, метки редактора и следы секретов в страницах, файлы больше 95 МБ и сайт больше 1 ГБ.
