# Контент сайта

Все тексты, разделы, услуги, контакты и проекты лежат в этой папке в JSON-файлах.
Код и шаблоны менять не нужно: отредактируйте файл, сохраните и обновите страницу
(файлы читаются при каждом запросе, перезапуск не нужен).

После любой правки запустите проверку:

```bash
flask --app app check-content
```

Она найдёт ошибки JSON (с номером строки), неверные ссылки между файлами,
несуществующие фото и т. п. Если JSON сломан, сайт отдаёт ошибку 500 — поэтому
проверяйте перед публикацией.

Поля, начинающиеся с `_` (`_comment`, `_icons`, `_walls`), — подсказки, сайт их не читает.

| Файл | Что в нём |
|---|---|
| `site.json` | Название компании, title/description страницы, кнопки шапки и подвала, форма заявки |
| `home.json` | Первый экран (hero) и блоки главной страницы по порядку |
| `pages.json` | Разделы-шторки с адресом `/slug` и пунктом меню, по порядку |
| `contacts.json` | Контакты для раздела «Контакты» |
| `portfolio.json` | Проекты портфолио |
| `media/` | Фотографии (отдаются по адресу `/media/...`) |
| `originals/` | Исходные файлы фото, загруженных через админку (сайт их не отдаёт) |

## Админ-панель (`/admin`)

Проекты портфолио и их фото можно вести в браузере, без правки JSON.
Админ-панель **выключена**, пока не заданы три переменные окружения — до этого
`/admin` отвечает 404. Пароль и ключи в код и в репозиторий не кладутся.

### Первый администратор

```bash
source .venv/bin/activate

# 1. Секретный ключ сессий (один раз; храните как пароль)
python3 -c "import secrets; print(secrets.token_hex(32))"

# 2. Хеш пароля: команда спросит пароль дважды (не короче 12 символов)
#    и выведет хеш. Сам пароль нигде не сохраняется.
flask --app app hash-password
```

Затем задайте переменные **в одинарных кавычках** (в хеше есть символы `$`):

```bash
export SECRET_KEY='…ключ из шага 1…'
export ADMIN_USERNAME='admin'
export ADMIN_PASSWORD_HASH='scrypt:32768:8:1$…хеш из шага 2…'

flask --app app run --debug
```

Откройте http://127.0.0.1:5000/admin и войдите. Удобно держать эти строки в файле
`.env` (он в `.gitignore`) и подключать `set -a; source .env; set +a`.

Сменить пароль — сгенерировать новый хеш и заменить `ADMIN_PASSWORD_HASH`;
после перезапуска все открытые сессии завершатся. Выключить панель — убрать
любую из трёх переменных.

### Что умеет

- создавать проект сразу с фото: «Добавить проект» → название компании / стенда, выставка, месяц,
  год, площадь (м², можно дробную: 40,5), планировка стенда (Угловой, Остров, Линейный, Полуостров),
  по желанию описание и ссылка Vimeo или Rutube, выбрать несколько фото →
  «Сохранить проект» (галочка «Опубликовать сразу» включена по умолчанию; без фото проект остаётся
  черновиком). Старые поля (город, категория, характеристики, «Пример») в форме больше не показываются,
  но из `portfolio.json` не удаляются и на сайте выводятся как раньше;
- загружать сразу несколько фото, менять их порядок, выбирать обложку (первое фото), удалять;
- импортировать проект из папки на компьютере: «Проекты» → «Импортировать папку» (ниже);
- добавлять фото в существующий проект на его странице; те же файлы (по содержимому) второй раз не
  добавляются — сообщение «уже есть в проекте»;
- по желанию — импортировать стенд из ZIP (свёрнутый блок «Дополнительно» на странице «Проекты», ниже);
- публиковать и снимать с публикации (без фото опубликовать нельзя);
- удалять проект (с подтверждением).

Список «Проекты» — дерево «год → месяц → выставка → проекты»: годы и месяцы от новых к старым
(декабрь… январь, «Месяц не указан» — в конце года), выставки и проекты — по названию; группы
сворачиваются, раскрыт последний год («Развернуть все годы» — все). Сверху — поиск по названию
компании/стенда и выставки и фильтры по году, месяцу, выставке и планировке (применяются кнопкой
«Показать»; адрес с фильтрами можно сохранить). Проекты без планировки видны только при «Все».
Проекты без года — в группе «Без даты» в конце.

### Выставки

Выставка — событие конкретного года: «Мебель» 2025 и «Мебель» 2026 — разные выставки; регистр и
лишние пробелы не различаются (« мебель » = «Мебель» в том же году — одна выставка). В поле «Выставка»
формы проекта браузер подсказывает уже известные названия (с годами); если такая выставка в выбранном
году есть, проект привязывается к ней с её написанием, иначе появляется новая — об этом сообщение.
Раздел «Выставки» показывает выставки по годам и их проекты; там же можно заранее добавить выставку
(название + год) и убрать добавленную, пока у неё нет проектов. Заранее добавленные хранятся в
`content/exhibitions.json` (`{"exhibitions": [{"name": "Мебель", "year": 2026}]}`, файл необязателен);
выставки из проектов берутся из `portfolio.json` автоматически. Месяц хранится в проекте.
Сайт показывает проекты в том же порядке (год и месяц от новых к старым, при равной дате — по
названию), без деления на месяцы. Ручной порядок (кнопки ↑ ↓, поле `order`) больше не используется.

Фото черновика видит только вошедший администратор; посетителям `/media/...` отвечает 404.

### Импорт папки

«Проекты» → «Импортировать папку» → выбрать папку одного проекта (например, «Агрос. Трансфаир 40м2»).
Страница сама оставит только фото JPG, PNG и WebP (PDF, Thumbs.db, .DS_Store не загружаются), подставит
название из имени папки (его можно поменять), покажет миниатюры в порядке имён файлов — их можно
переставить (← / →), убрать и выбрать обложку («Сделать обложкой»). «Импортировать» — фото уходят обычной
формой создания проекта и обрабатываются так же, как при любой загрузке; по умолчанию проект — черновик.
Пределы те же: за раз до 20 фото, до 40 МБ каждое и 200 МБ всего — иначе кнопка недоступна, лишнее
можно убрать и добавить потом на странице проекта. Папка на компьютере не меняется; другие папки не
читаются. Для миниатюр и порядка нужен JavaScript (`static/js/admin-import.js`); без него форма тоже
работает — сервер пропустит не-фото, порядок будет как у файлов.

### Импорт стенда из ZIP

Не обязателен — обычно проще «Добавить проект» с выбором фото. «Проекты» → «Дополнительно: импорт
стенда из ZIP»: архив с одной папкой фото (или фото в корне архива), год и, по
желанию, название. Создаётся черновик: название — из поля или из имени папки (иначе — имя архива),
фото — в порядке имён файлов (`2.jpg` раньше `10.jpg`), первое — обложка. Фото проходят ту же
обработку, что и при обычной загрузке (оригинал байт в байт в `originals/`, WebP без EXIF и GPS),
пределы те же: архив до 200 МБ, не больше 20 фото по 40 МБ; не поместилось — догрузить на странице
проекта. Архив на диск не распаковывается. Мусор macOS и Windows (`__MACOSX`, `.DS_Store`,
`Thumbs.db`, скрытые файлы) пропускается молча, не фото и HEIC — с сообщением. Весь архив отклоняется,
если в нём пути с `..` или абсолютные, символические ссылки, шифрование, вложенные или несколько
папок, больше 20 фото или подозрительно сильно сжатые файлы. Если не загрузилось ни одного фото,
проект не создаётся. Исходные папки на компьютере (например, в `project_photos/`) импорт не меняет.

### Визуальный редактор (`/admin/editor`)

Слева — главная в предпросмотре (кнопки 390 / 768 / 1440 px — телефон, планшет, компьютер),
справа — поля. Нажмите на текст в предпросмотре — откроется и выделится его поле.
Все видимые посетителю тексты правятся здесь по группам: «Общие тексты» (название,
шапка, подвал, форма заявки, окна и галерея), «Первый экран», по группе на каждый
блок главной и на каждый раздел (`pages.json`), «Список контактов» (`contacts.json`).
Поля разделов и контактов выбираются в панели справа — в предпросмотре главной их не видно.

- «Сохранить черновик» — правки сохраняются в `content/.drafts/`, предпросмотр показывает
  черновик, **сайт не меняется**.
- «Опубликовать» — проверка контента и запись на сайт; прежняя версия уходит в `.history/`.
  Если тот же файл успели изменить в другом месте (например, вручную), публикация отказывает,
  чтобы не стереть ту правку, — отмените черновик и внесите изменения заново.
- «Отменить черновик» — удалить неопубликованные правки.
- «История версий» — прежние версии: «Посмотреть» открывает предпросмотр версии,
  «Восстановить в черновик» кладёт её в черновик (сайт не меняется до публикации).

Как заполнять поля:

- однострочные поля — заголовки, кнопки, подписи; многострочные — описания;
- списки (абзацы) — по одному пункту в строке, абзацы
  разделяются пустой строкой;
- пустое поле — используется текст по умолчанию (он показан в подсказке);
- адреса, slug, id, типы блоков, значки, стены и площадь конструктора, email заявок,
  `visible` и поля `_…` в форме не показываются — их меняют в JSON;
- неизвестные поля и порядок записей сохраняются; перед записью файл проверяется
  целиком, а если его изменили, пока редактор был открыт, сохранение отклоняется.

Фото, видео и структура блоков в редакторе пока не меняются.

Метки в фигурных скобках (`{year}`, `{company}`, `{n}`, `{type}` …) подставляются
сайтом — оставляйте их в тексте.

### Защита

- вход по логину и хешу пароля (scrypt); после 5 неверных попыток за 15 минут адрес
  блокируется на 15 минут; сессия живёт 8 часов, cookie `HttpOnly`, `SameSite=Lax`;
- CSRF-токен в каждой форме (включая вход и выход), выход — только POST;
- фото: только JPG (в том числе JPEG с блоком MPF — так снимают многие камеры и iPhone),
  PNG, WebP — тип проверяется по содержимому (Pillow), а не по имени; до 40 МБ на файл,
  до 20 файлов и 200 МБ за раз (4 фото по 40 МБ; 5 — если каждое чуть меньше 40 МБ),
  до 100 Мп (PNG и WebP — до 50 Мп: они декодируются целиком). Размер файла и разрешение —
  независимые пределы. Файл перекодируется в WebP (до 2560 px) с версиями 640/1280/1920 px,
  EXIF и геопозиция удаляются, имя задаёт сервер;
- исходный файл сохраняется как есть в `content/originals/portfolio/<id>/NN.jpg|png|webp`
  (тот же номер, что у фото). Папка вне `media/`, сайт её не отдаёт: в оригинале
  остаются EXIF и геопозиция. Если фото не удалось обработать, оригинал не теряется —
  он переносится в `content/.history/originals/<время>/…`;
- страницы панели не кешируются и закрыты от поисковиков (`no-store`, `noindex`).

### Резервные копии

Перед каждым сохранением прежняя версия `portfolio.json` копируется в
`content/.history/` (последние 500 копий каждого файла). Удалённые фото и папки проектов не стираются,
а переносятся в `content/.history/media/<время>/` (оригиналы — в
`content/.history/originals/<время>/`, с тем же временем). Вернуть — перенести файлы
обратно с той же структурой папок и добавить фото в проект.
Папку .history не очищайте вручную без предварительной проверки содержимого и плана резервного копирования. В ней хранятся предыдущие версии JSON и удалённые фотографии с оригиналами. Перед очисткой убедитесь, что необходимые данные сохранены в независимой резервной копии и их можно восстановить.

Архив всего контента (JSON, `media/`, `originals/`, `.history/`, `.drafts/`; без `.cache/` и `.lock`)
делает `scripts/backup-content.sh` — в `~/CRVU-backups` или в папку из `CRVU_BACKUP_DIR`,
под той же блокировкой, что и админка; старые архивы не удаляются и не перезаписываются.
Храните архивы вне этого компьютера (внешний диск, облако). Проверка и восстановление —
только во временную папку, не поверх рабочего `content/`:

```bash
scripts/backup-content.sh
mkdir -p /tmp/crvu-restore && tar -xzf ~/CRVU-backups/crvu-content-<дата>.tar.gz -C /tmp/crvu-restore
CRVU_CONTENT_DIR=/tmp/crvu-restore/content CRVU_ENV_FILE= flask --app app check-content
```

### Подборки фото стендов (`project_photos/`)

Подготовленные фото можно держать в корне проекта, рядом с `content/`: `project_photos/<стенд>/01.jpg`,
`02.jpg`… — одна папка на стенд. Это отдельное хранилище исходных подборок: сайт его не раздаёт и не
читает, с `portfolio.json`, `content/media/` и `content/originals/` оно не связано, в Git не попадает.
В портфолио фото попадают только загрузкой в админке (в том числе импортом ZIP, выбранного вручную);
исходные папки при этом остаются на месте.
Архив подборок (отдельный от архива контента, в ту же папку `CRVU_BACKUP_DIR` или `~/CRVU-backups`):

```bash
scripts/backup-project-photos.sh
```

При переносе на сервер переносить: код (`app/`, `scripts/`, `requirements.txt`), весь `content/`
(вместе с `originals/`, `.history/`, `.drafts/`; без `.cache/` и `.lock`) и `project_photos/`,
если подборки нужны и там (вне папки, которую раздаёт веб-сервер); `.env` — не переносить, на
сервере создать свой.

### На боевом сервере

- запускать без `--debug` (например, `gunicorn "app:create_app()"`), `FLASK_DEBUG` не задавать;
- только HTTPS и `SESSION_COOKIE_SECURE=1`;
- папка `content/` должна быть доступна приложению на запись и не теряться при
  обновлении кода; делайте её резервные копии;
- блокировка попыток входа хранится в памяти процесса: при нескольких воркерах
  у каждого свой счётчик, после перезапуска счётчик обнуляется. За прокси
  (nginx) без `ProxyFix` все запросы приходят с адреса прокси — тогда блокировка
  срабатывает для всех сразу; настройте `ProxyFix` под свой прокси;
- блокировка файлов (`fcntl`) работает на Linux/macOS, не на Windows;
- загрузка фото: у прокси предел запроса чуть выше, чем у админки (200 МБ) — nginx
  `client_max_body_size 210m;`; при равном пределе слишком большую пачку отклонит сам nginx
  своей страницей 413, а не админка понятным сообщением. Таймауты — с запасом: JPEG на 40 МБ
  (38 Мп) обрабатывается около 3 с, пачка из 4 таких — около 12 с (nginx `proxy_read_timeout 120s;`,
  gunicorn `--timeout 120`). nginx по умолчанию сначала принимает весь запрос, и время передачи
  по сети в таймаут gunicorn не входит; при `proxy_request_buffering off` — входит. Временные файлы
  загрузки (до 200 МБ на запрос) пишутся во временную папку — на ней нужно место. Памяти — не
  меньше 1 ГБ на воркер: пик зависит от числа пикселей, а не от размера файла (JPEG 3:2 на 38 Мп —
  около 0,7 ГБ, панорама на 96 Мп — около 0,4 ГБ, PNG на 50 Мп — около 0,7 ГБ). Фото обрабатываются
  по одному (блокировка `content/.lock`), поэтому пик не умножается на число воркеров;
- загрузка видеоотзывов: файл до `CRVU_MAX_VIDEO_MB` (по умолчанию 180 МБ), запрос — видео плюс 20 МБ
  на обложку (по умолчанию 200 МБ: прежние `client_max_body_size 210m`, `proxy_read_timeout 120s` и
  gunicorn `--timeout 120` подходят). Подняли `CRVU_MAX_VIDEO_MB` — поднимите и `client_max_body_size`
  (больше суммы на 10 МБ). Видео копируется на диск потоком, без обработки — памяти почти не нужно, нужно
  место: в `content/media/videos/` и во временной папке (nginx и Werkzeug держат файл там до конца запроса).
  Отдавать видео лучше nginx (поддерживает Range — перемотку); раздаёт и Flask (`send_from_directory`
  тоже понимает Range, но держит воркер всё время передачи);
- если `/media/` отдаёт сам nginx, укажите только `content/media/`: папку
  `content/originals/` наружу не открывать — в оригиналах EXIF и геопозиция. Учтите: nginx отдаёт файлы
  напрямую, мимо проверки «только администратору» — неопубликованные фото портфолио и видео будут видны
  по прямой ссылке. У видео и обложек имена случайные (128 бит), угадать их нельзя, но ссылку из черновика
  лучше никому не пересылать. Если нужна строгая проверка — отдавайте `/media/portfolio/` и
  `/media/videos/files/`, `/media/videos/covers/` через приложение.

## Проекты и фото

1. Создайте папку `media/portfolio/<id>/` и положите туда фото
   (`.jpg`, `.jpeg`, `.png`, `.webp`, `.avif`). Удобно называть `01.jpg`, `02.jpg`… —
   порядок по имени файла.
2. Добавьте запись в `projects` файла `portfolio.json`:

```json
{
  "id": "expo-2026-stand",
  "status": "draft",
  "title": "Стенд компании на выставке",
  "category": "Двухэтажный",
  "exhibition": "Название выставки",
  "city": "Москва",
  "year": 2026,
  "month": 10,
  "area": 40.5,
  "description": "Короткое описание проекта.",
  "cover": "",
  "photos": [],
  "specs": [
    {"label": "Площадь", "value": "120 м²"},
    {"label": "Срок застройки", "value": "3 дня"}
  ],
  "video": ""
}
```

- `id` — латиница в нижнем регистре, цифры и дефис; уникальный. Совпадает с именем папки фото.
- `status` — `draft` (не показывается) или `published` (на сайте). Удобно сначала
  добавить как `draft`, проверить `check-content`, затем опубликовать.
- `year` — число; проект попадает во вкладку этого года.
- `month` — месяц числом 1–12 (10 — октябрь). Порядок на сайте и в админке — по году и месяцу, от
  новых к старым, при равной дате — по названию. Без `month` проект стоит после месяцев своего года.
- `layout` — планировка стенда: `"Угловой"`, `"Остров"`, `"Линейный"` или `"Полуостров"` (ровно так).
  Обязательна для новых проектов (форма, импорт папки, ZIP) и для публикации. У старых проектов её может
  не быть: они открываются и сохраняются без неё, пока планировку не выберут; выбранную убрать нельзя.
  Опубликованные старые проекты остаются на сайте. На сайте планировка пока не показывается.
- `floors` — этажность: `1` (одноэтажный) или `2` (двухэтажный); необязательно. В админке — поле
  «Этажность» («Не указана» — поле не записывается). Не по тексту описания: без поля стенд виден в
  портфолио только при «Любая этажность».
- Фильтры портфолио на сайте: планировка (`layout`), площадь (`area`: до 12 м², 12–30, 30–60, более 60;
  граница — в нижнем диапазоне) и этажность (`floors`). Без значения стенд виден без этого фильтра и не
  попадает ни в одну конкретную категорию. Выбор сохраняется в адресе (`/portfolio?layout=…&area=…&floors=…`).
- `area` — площадь в м², число больше нуля (`40` или `40.5`); на сайте — «Площадь: 40,5 м²» вместо
  старой характеристики «Площадь». Пока `area` нет, показывается характеристика из `specs`.
- `order`, `category`, `city`, `example` — старые поля: форма их не показывает и не меняет, `order` на
  порядок больше не влияет.
- `exhibition` — группа внутри года; без неё проект попадает в «Другие проекты».
- `photos` — пустой список: берутся все фото из `media/portfolio/<id>/`.
  Можно перечислить явно: `["portfolio/expo-2026-stand/02.jpg", ...]` (пути от папки `media/`).
- `cover` — обложка карточки (путь как в `photos`); если пусто — первое фото.
- `specs` — характеристики в окне галереи, любые пары «название — значение».
- `video` — ссылка на видео **Vimeo** или **Rutube** либо пусто.
  Vimeo: `https://vimeo.com/123456789`, закрытое видео — со вторым кодом
  `https://vimeo.com/123456789/abcdef1234` (подходят и ссылки каналов, подборок, `player.vimeo.com/video/…`).
  Rutube: `https://rutube.ru/video/<код из 32 символов>/`, закрытое видео — ссылка «Поделиться» с ключом
  `https://rutube.ru/video/private/<код>/?p=<ключ>` (подходят и `rutube.ru/shorts/…`, `rutube.ru/play/embed/…`).
  Другие сайты не принимаются. В галерее стенда появляется кнопка
  «Смотреть видео»: плеер загружается только после нажатия (без автозапуска) и удаляется
  при возврате к фото и закрытии окна; под карточкой портфолио — ссылка на страницу видео.
- `example: true` — пометка демонстрационных данных. Все текущие проекты `example-*`
  и `test-arara` — примеры из исходного файла: кадры анимации вместо фото и
  выдуманные названия выставок. Перед запуском их нужно заменить или удалить
  (или поставить `"status": "draft"`).

У опубликованного проекта должна быть хотя бы одна фотография — иначе `check-content` сообщит об ошибке.

Диапазон годов во вкладках: от текущего года до `first_year` раздела портфолио
в `pages.json` (расширяется автоматически, если есть проекты старше или новее).

## Блоки главной страницы (`home.json` → `sections`)

Блоки выводятся в порядке списка. Чтобы поменять порядок — переставьте записи.
`"visible": false` — блок скрыт. Типы:

- `projects` — «Реализованные проекты»: до 6 крупных карточек и кнопка `button` +
  `button_page` («Смотреть все проекты»). Карточка в `items`:
  `{"project": "", "title": "", "event": "", "area": "", "place": "", "image": ""}`.
  `project` — id опубликованного проекта из `portfolio.json`: название, выставка, город,
  площадь (характеристика «Площадь…») и фото берутся оттуда, «Подробнее» открывает его
  галерею. Свои поля важнее: `title` — название, `event` — выставка, `area` — площадь,
  `place` — город/страна, `image` — фото, путь от `content/media/` (например
  `home/project-1.webp`; инструкция — `content/media/home/README.txt`). Пустые поля
  на сайте не показываются — ничего не додумывайте.
  Карточки идут **ровно в порядке `items`**: проекты выбирают и расставляют в «Редакторе»
  («Выбрать проекты…» — поиск по компании или выставке, ↑/↓, ✕, затем «Опубликовать»).
  Год и месяц проекта не важны — можно выбрать любой опубликованный проект; автоотбора
  по дате нет (старое поле `latest` не действует и убирается при сохранении выбора).
  Черновик или удалённый из портфолио проект на главной не показывается, ошибки нет.
  Карточка без фото — **временная заглушка**: на сайте её нет, пока не задано
  `CRVU_SHOW_PLACEHOLDERS=1` (только для просмотра макета, не на боевом сервере).
  Если все карточки без фото, блок скрыт, а вторая кнопка первого экрана ведёт в раздел
  портфолио. `flask --app app check-content` напоминает о карточках без фото.
- `configurator` — конструктор стенда с ориентиром бюджета. `area` — `min`, `max`, `default` (м²);
  `types` — типы стенда (`walls`: закрытые стороны `back`/`left`/`right` на схеме). Выбранные
  размер, тип, уровень, опции и ориентир подставляются в заявку («Обсудить проект»). С 16.10.2026
  старые «Опции» и второй этаж убраны: `options`, `options_label`, `options_summary`, `deck_note`
  и тип с `deck: true` («Двухэтажный») сайт и редактор не используют — их можно удалить. С 30.10.2026
  нет и поля «Бюджет, ₽» (`budget_label`, `budget_hint`, `budget_summary` не используются): его
  заменил ориентир; бюджет в старых заявках по-прежнему виден в админке.
  Подписи: `size_label`, `length_label`, `width_label`, `area_label`, `decrease_label`,
  `increase_label`, `type_label`, `level_label`, `extras_label`, `extras_hint`, `extras_count` (`{n}`),
  `plan_label`, `submit`; блок ориентира: `result_title`, `result_area`, `result_area_value`
  (`{area}`, `{length}`, `{width}`), `result_config`, `result_config_value` (`{type}`, `{level}`),
  `result_rate`, `result_total`, `engineering_note` (`{names}`), `open_ended_note`, `estimate_note`;
  заявка: `summary_text` (`{type}`, `{length}`, `{width}`, `{area}`), `level_summary` (`{level}`),
  `extras_summary` (`{extras}`), `estimate_summary` (`{range}`), `request_intro`; план:
  `plan_caption` (`{type}`), `open_sides` (`{n}`). Не заданы — используются тексты по умолчанию.

  **Ориентир бюджета — `pricing`** (формула — `app/static/js/stand-price.js`, проверка —
  `flask --app app check-content`). Это предварительная модель для калибровки, а не прайс:
  она не проверена на прошлых проектах и не является коммерческим предложением.
  - `rate.small` и `rate.large` — две точки калибровки ставки «от» за м² (сейчас 10 м² — 70 000 ₽,
    100 м² — 35 000 ₽). Между ними и за ними ставка идёт по степенной кривой
    `ставка(S) = small.rate_min × (S / small.area)^(−k)`, `k = ln(small.rate_min / large.rate_min) /
    ln(large.area / small.area)`: с ростом площади она только снижается, а сумма растёт.
    `large.rate_max` (45 000 ₽) задаёт верх диапазона: «до» = «от» × rate_max / rate_min на любой площади.
    Ставка за м² не может расти с площадью — `check-content` не пропустит такие числа.
  - `open_sides` — множитель по числу открытых сторон: «1» линейный … «4» остров.
  - `levels` — уровни сложности: `id`, `name`, `text` (описание), `factor` (множитель),
    `open_ended: true` — без верхней границы («от …»).
  - `extras` — опции: `kind: "percent"` — доля базы (`min`–`max`, 0,15 = +15 %);
    `"urgent"` — надбавка к производству (база с опциями percent, без экранов);
    `"fixed"` — сумма в рублях; `engineering: true` — нужен инженерный расчёт, верхней границы нет.
  - `round` — округление итога, ₽ (ставка за м² округляется до 100 ₽).
  Названия и описания уровней и опций правятся в «Редакторе»; числа — только здесь.
  Ориентир в заявке посчитан в браузере клиента — в админке он помечен «ориентир с сайта».
- `about` — «Компания в цифрах»: `{"type": "about", "id": "company", "visible": true}`.
  Свои данные блок не хранит — цифры, год основания и абзацы берутся из раздела `about`
  в `pages.json` (ниже; правятся в «Редакторе», группа «Раздел: О нас»). Первые три цифры
  `stats` — крупно, в три колонки; год основания (`since_text`) и остальные цифры — мелкой
  строкой под ними. Пока блок виден, у «О нас» нет своей шторки: пункт меню ведёт к блоку,
  адрес `/about` — туда же. `id` блока не должен совпадать со slug раздела (`about`).
- `faq` — «Частые вопросы»: `title` и `items` — `{"question": "…", "answer": "…"}`
  (оба поля обязательны, до 20 вопросов). Аккордеон: открыт один ответ, вся строка вопроса —
  кнопка. Стоит последним блоком — сразу перед подвалом «Обсудим ваш следующий проект».
  Вопросы и ответы правятся в «Редакторе» (группа «Вопросы: …»).
- `text` — простой текстовый блок:

```json
{"type": "text", "id": "why-us", "visible": true, "title": "Почему мы", "lead": "", "paragraphs": ["Абзац 1", "Абзац 2"]}
```

`id` — уникальный (латиница, цифры, дефис), служит якорем `/#id`.
Первый экран настраивается в `hero`: `primary_target` — id блока, к которому ведёт
главная кнопка; `secondary_action: "request"` — вторая кнопка открывает форму заявки;
без него `secondary_target` — id блока для второй кнопки (если блок не показан —
используется `secondary_page`, slug раздела); `facts` — короткая строка под кнопками
(список пунктов, пустой — строка скрыта).

## Видеоотзывы (`videos.json`)

Видео — ссылка на ролик RuTube или свой файл MP4/WebM, загруженный в админке. Всё управление — только
в «Редакторе», группа **«Видеоотзывы»**: библиотека, выбор трёх видео на главную и подписи блока.
Отдельного раздела в меню админки нет. Как и тексты, любые изменения сначала попадают в черновик:
проверить предпросмотр → «Опубликовать» (прежняя версия `videos.json` — в «Истории версий»).
Файл необязателен: пока его нет, блок «Нам доверяют свои проекты» показывает заглушки.

- **«+ Добавить видео»** (в группе и в окне «Выбрать видео…»): переключатель «Ссылка RuTube» /
  «Файл с компьютера», название и короткое описание по желанию, обложка. «Сохранить видео» сразу кладёт
  ролик в черновик — страница не перезагружается, видео тут же появляется и в библиотеке, и в окне выбора
  (в окне его можно сразу отметить, выбор и порядок не сбрасываются).
  - **RuTube:** `https://rutube.ru/video/<код>/` или `https://rutube.ru/play/embed/<код>` (подходят
    закрытые ролики с `?p=…` и shorts). «Показать видео» проверяет ссылку и показывает плеер. Код iframe
    не принимается: сохраняются код ролика и ссылка, адрес плеера сайт собирает сам.
  - **Файл:** MP4 (H.264) или WebM, до 180 МБ (`CRVU_MAX_VIDEO_MB`). Файл хранится как есть — сервер
    видео не пережимает (ffmpeg не используется), поэтому нужен формат, который браузеры играют сами.
    Тип проверяется по содержимому файла; MOV (QuickTime, iPhone) и MKV не принимаются — сохраните видео
    в MP4 (H.264). Если браузер не может воспроизвести выбранный файл (например, MP4 с HEVC), форма
    предупредит до загрузки. Во время загрузки — полоса прогресса и «Остановить загрузку».
- **Обложка:** по умолчанию у RuTube — копия картинки ролика (`content/media/videos/<код>.webp`, сервер
  скачивает её один раз; `CRVU_VIDEO_THUMBNAILS=0` выключает скачивание), у файла — кадр в начале видео.
  Свою обложку можно выбрать при добавлении или кнопкой «Обложка…» у видео: «Загрузить картинку…»
  (JPG, PNG, WebP) или, у файла, «Взять текущий кадр» — поставьте видео на нужный момент. Предпросмотр
  обложки — до сохранения. «Вернуть обложку RuTube» / «Убрать свою обложку» — снова обложка по умолчанию.
- **«Все видео»:** карточки с обложкой, источником («RuTube» / «Файл») и номером на главной; поиск по
  названию и описанию. Галочка «Показывать на сайте» (выключенное видео скрыто и убирается с главной, но
  остаётся в библиотеке), ↑/↓ — порядок (он же порядок в окне «Другие видео-отзывы»), «Смотреть» — плеер
  под карточкой, «Изменить подписи» (у RuTube — и ссылку: новый ролик встаёт на то же место), «Удалить…» —
  с подтверждением; до публикации удаление отменяет «Отменить черновик».
- **На главной:** «Выбрать видео…». Окно как у «Реализовано»: сверху «Видео на главной» (номер, обложка,
  название, ↑/↓, ✕, перетаскивание), снизу карточки включённых видео с поиском. До трёх видео;
  «Готово» → «Сохранить черновик» → «Опубликовать». Свободное место — заглушка «Скоро здесь будет видео».
- **«Другие видео-отзывы →»** под карточками открывает шторку `/video-reviews` со всеми включёнными
  видео, кроме стоящих на главной. Нет таких видео — нет ни кнопки, ни шторки.
- На сайте плеер загружается только по нажатию на карточку: RuTube — плеер RuTube, файл — встроенный
  плеер браузера с обложкой. До нажатия видео не скачивается. Без JS карточка — ссылка на ролик.
- Подписи блока (кнопка, заголовок шторки, «Смотреть видео», заглушка) — там же, в группе
  «Видеоотзывы» (`more_button`, `more_title`, `play_label`, `video_error`, `video_open`,
  `placeholder`, `caption`).

### Где лежат файлы видео

| Путь | Что |
|---|---|
| `media/videos/files/<32 символа>.mp4\|.webm` | загруженные видео (имя случайное, существующие файлы не перезаписываются) |
| `media/videos/covers/<32 символа>.webp` | свои обложки (картинка или кадр, до 1920 × 1080) |
| `media/videos/<код RuTube>.webp` | копии картинок RuTube |

Пока видео не опубликовано и не включено, `/media` отдаёт его файл и свою обложку только вошедшему
администратору (посетителю — 404). Файлы не удаляются: после «Опубликовать» и «Отменить черновик»
файлы, на которые не ссылаются ни сайт, ни черновик, ни одна сохранённая версия в «Истории версий»,
переносятся в `content/.history/media/<время>/videos/…`. Поэтому восстановленная из истории версия
находит свои видео, а место на диске со временем растёт — старые копии в `.history/media` можно
архивировать вручную.

```json
{"videos": [{"id": "1a2b3c4d", "rutube": "<код>", "url": "https://rutube.ru/video/<код>/",
             "title": "", "description": "", "active": true},
            {"id": "5e6f7a8b", "file": "videos/files/<32 символа>.mp4", "cover": "videos/covers/<32 символа>.webp",
             "title": "", "description": "", "active": true}]}
```

`id` — постоянный номер записи (8 символов 0–9, a–f; не меняется при замене ссылки). У ролика RuTube —
`rutube` (код, 32 символа) и `url` (ссылка на тот же ролик), у загруженного — только `file`. `cover` —
необязательная своя обложка у обоих. Название — до 120, описание — до 300 символов. Позиции на главной —
`home.json` → блок `reviews` → `items`: `{"video": "<id>"}` или `{}` (заглушка), до трёх разных видео.
Проверка (в том числе наличие файлов) — `flask --app app check-content`.

## Разделы с адресом (`pages.json` → `pages`)

Каждый раздел открывается шторкой по адресу `/slug` и появляется в меню
в порядке списка (`nav` — текст пункта меню). `"visible": false` — раздел убран
из меню, а адрес отдаёт 404. Типы:

- `portfolio` — портфолио (только один); подписи `tabs_label`, `example_badge`,
  `photo_count` (`{n}`), `empty` (`{year}`);
- `about` — «О нас»: `founded_year`, `since_text`, `paragraphs`, `stats_title`,
  `stats` (`value` — целое число, `suffix`, `label`; первые три — главные цифры).
  Если на главной есть блок `about`, раздел показывается там, а не шторкой;
- `contacts` — контакты из `contacts.json`; `empty` — текст, пока контактов нет;
- `text` — произвольная текстовая страница:

```json
{"slug": "delivery", "type": "text", "visible": true, "title": "Доставка и монтаж", "nav": "Доставка", "paragraphs": ["Абзац 1", "Абзац 2"]}
```

`slug` нельзя брать из занятых: `static`, `media`, `main`, `request`, `gallery`,
`admin`, `api`, и он не должен совпадать с id блока главной.

## Контакты (`contacts.json`)

Пустые значения не показываются. `type`: `phone` (ссылка `tel:`), `email`
(`mailto:`), `link` (только `http://`/`https://`), `address` и `text` — без ссылки.
Порядок — как в списке; можно добавлять свои записи.

Контакты показываются в разделе «Контакты» и в подвале. Почта сайта — одна запись
`type: "email"`: её `value` (сейчас `info@crvu.ru`) подставляется в оба места,
её же копирует кнопка рядом с адресом. Меняйте адрес здесь или в админке
(«Редактор» → «Список контактов» → Email, затем «Опубликовать»); пустое значение скрывает почту.
Адрес для писем из формы заявки — отдельная настройка (`site.json` → `request.email`).

Соцсети и мессенджеры — список `socials` в том же файле: `network` (`telegram`, `max`, `vk` —
выбирает значок), `label` (подпись) и `url` (только `http://`/`https://`, пустой — ссылка скрыта).
Показываются в разделе «Контакты» под контактами, открываются в новой вкладке. Заголовок блока —
`pages.json` → раздел `contacts` → `socials_title`. Подписи, ссылки и заголовок правятся в админке
(«Редактор» → «Список контактов» и «Раздел: Контакты»).

## Заявки (`site.json` → `request`)

Серверная отправка заявок **не реализована**. Поведение формы:

- `email` пустой — заявка не отправляется, пользователь видит `offline_message`;
- `email` заполнен — кнопка открывает почтовую программу посетителя с готовым
  письмом на этот адрес (`subject` — тема). Письмо уходит, только если посетитель
  сам нажмёт «Отправить» в почте.

Для приёма заявок на сервере нужна отдельная доработка (обработчик POST,
CSRF-защита, отправка почты или сохранение).

Подписи формы: `title`, `name_label`, `contact_label`, `message_label`, `submit`,
`cancel`, `note_email`, `note_offline`; `body_name` и `body_contact` — подписи
строк в тексте письма.

## Подписи интерфейса (`site.json` → `ui`, `footer`)

`ui`: `menu`, `menu_label` (для экранных дикторов), `logo_label`, `skip_link`,
`close`, `photo_prev`, `photo_next`, `photo_alt` (`{title}`, `{n}`, `{total}`),
`photo_thumb` (`{n}`), `video`. `footer.copy` — строка внизу, `{year}` и `{company}`
подставляются. Пустые и отсутствующие поля заменяются текстом по умолчанию.
